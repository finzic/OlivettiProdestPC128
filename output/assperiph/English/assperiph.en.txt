Introduction

There are two parts to this book that are oriented differently but built in the same perspective.

First it allows you to learn how to program your MOS and TO7/70 directly in the language that the microprocessor understands, the machine language. Machine language offers you many advantages over BASIC, including considerable speed gain (a machine language program runs ten to a thousand times faster than a sasic program) and also a memory saving. Despite its rebarbatory side at first glance, you will quickly be conquered by its capabilities.

Then it offers you the possibility to use the routines found in ROM, in the section entitled "Useful Routines and Addresses". This set of tricks and tricks allows the programmer to save time and space. This part is not intended to be exhaustive because our research has not allowed us to discover everything.

The only imperative before approaching the reading of this book is to have fully assimilated BASIC and the basic concepts of programming that we will not return to. If so, we hope that this book will allow you to familiarize yourself with your MO5 so that you can extract the quintessence.

Without further delay, let us go to the "serious things" without forgetting to thank the Loriciels company for its cooperation in the preparation of this book.

OVERVIEW

This book is intended as an introduction to machine language and assembler programming on MOS, and it is quite possible that you have no idea what this mode of programming is.

In fact, the difference between machine language and assembly language, or their specificities in relation to BASIC, can be totally alien to you. So let's look at the simplified operation of the computer together:

In MO5, this CPU is a 6899E and we will see that this circuit can only understand a very particular language and difficult to decipher by a human.

When you communicate with your MO5, you send the information via the keyboard. This information is then encoded by the operating system and translated into electrical impulses. It is only from this stage that the information reaches the CPU and can understand it. In fact, your information is translated by the operating system to be understandable by the machine. This translator is called "BASIC interpreter".

Now let's see how the electrical impulses get to the CPU.

On all pins of the circuit, eight are used for this purpose. He can therefore accept only eight signals simultaneously. When you combine these signals, you get a machine code. By convention, we note the presence of 5 volts on a pin by a 1, and that of @ volt by a 9. This results in either 0 or 1; We are therefore based 2 or binary. These numbers are called bits (English, Binary Digits) and are the basic unit of information. Associated by eight, the byte group is named.

As can be seen, information reaching the CPU is 1909 0119. 1900 9119 is an byte, eight-bit association. If we compare, for example, the machine language operation, 19999119 11111111, etc. of the Basic, LET A = 255, we see a slight difference and a more rebarbative side of the d-bytes group because as this good lord of PALICE would have said, machine language is a language for... machines!

But it's a joke, because you have to ask yourself: "Why bother yourself with all these numbers when you can use advanced languages like
le BASIC, le FORTH... ? »

Let's try to answer by comparing an advanced language, in this case BASIC, with a low-level language, in this case machine language.

DISADVANTAGES OF MACHINE LANGUAGE

B impossibility of adapting to other computers: the portability of Basic already poses certain problems according to its type. Machine language is practically insolvent because a program is system specific (it is not enough to have the same microprocessor).

m Hard-to-read programs. and to be corrected: a sequence of numbers is not very expressive, even if there is equivalence with a so-called assembly language (see below). Moreover, the identification of the error is quite critical.

# Difficult arithmetic calculations: Managing floating point numbers is very complicated. If it is really needed, it is better to use advanced and specialized language such as PASCAL, for example.

m= Need for more important learning: Basic learning takes a few weeks, machine language learning takes much longer because it requires a lot of rigour and attention.

# Difficult structuring of a programme: there is no question, for example, of adding instructions inside, if there is no room for this (unless there is a assembler, see below). Everything must be thought of, otherwise the work of modification is very important.

ADVANTAGES OF MACHINE LANGUAGE

m Maximum speed of execution: much time is lost by the interpretation of a Basic order. The differences are flagrant between the two languages and it can be saved up to a hundred times in execution time.

# More rational use of memory size: a program written in machine language occupies less space in memory and thus allows to make very powerful programs with 32 K.

The only limits are practically those of your imagination.

= Use of all computer resources: MO5 has virtually untapped possibilities in Basic.

= Possibility of combining Basic and machine language: a program does not always require absolute speed in all its parts. Only a few can be written in machine language and used as sub-programs, the others will be in BASIC.

BASIC DIFFERENCES

m No variables within the meaning of the Basic: there are only internal registers in the microprocessor (see Chapter 3). They do not really match the BASIC variables themselves.

m No lines: in machine language the instructions follow according to their memory addresses, while the lines are listed according to their numbers. For example, you can lengthen or shorten a line, or even add one; the readjustment is automatic whereas it is not mentioned in machine language (unless you have a assembler, see below).

# No syntax correction: if an error is made in machine language, the computer has every chance of "planting" itself and there is only the solution left to disconnect the power supply!

ASSEMBLY LANGUAGE

The only difference with machine language is the greatest ease of understanding for a human. As a result, the assembly language is not really understandable by the machine. In fact, it is an adaptation into a language more legible than a succession of bytes.

But be careful, it is only a translation, like that of an advanced language, of each code in the form of abbreviations called MNEMONICS. By abuse of language, they say it's equivalent.

This process translates for example 19999119 11111111 by LDA # FF$. This means "put SFF in Register A" (LD being the abbreviation of LOAD, load in English).

CONCLUSION

When you design a program, you will do so in the form of MNEMONICS, which you will then translate into machine code, either using tables or using a program called ASSEMBLEUR, such as the Monitor-Assembler-Disassembly ODIN software, marketed by LORICELS.

All this is complicated, long, confusing, distasteful, but you will be very satisfied with your achievements, be sure!

We have seen in the previous chapter that information is coded as numbers called bytes and that each byte consists of eight bits. When talking about information, it is necessary to differentiate, on the one hand, the representation of instructions, and on the other hand the representation of data: the former have one or more bytes specific to each instruction, this is the set of instructions that we will see below; Seconds have a much more complicated representation for which we have to distinguish several cases. ~

SIGNED BINARY REPRESENTATION

We have seen that by previous representations only natural integers can be coded. The representation here allows to encode the relative integers. In this mode, the sign is given by the higher weight bit (MSB). We use an @ for a positive number and a 1 for a negative number.

Thus:
01901991 représente + 73;
11991991 représente — 73.

The use of bit number 7 for sign can only be used to code numbers with an absolute value of less than 128.

This representation is not ideal, however, because if we try to add a negative number and a positive number, the negative being greater in absolute value (because of its number 7 which is worth 1), the result will be wrong. That's why we introduced another representation.

REPRESENTATION IN ADDITION TO TWO

With this system, the positive numbers have the same representation as in binary signed, the difference is visible for the negative numbers. The representation of a negative number is done by complementing this number (i.e. inverting each bit 1 in @ and @ in 1) and adding 1.

THE BATTERY CONCEPT

In the paragraph concerning address modes, it was assumed that the exact address, or at least a relationship with an exact address, was known for any address. However, it is true that in many programs, some applications require that the microprocessor does not work with known memory locations, but rather with a stack system. It is a set of memory locations for which the CPU has a specific address generator that allows access to these locations. The address generator uses the stacking-skinning concept.

The classic example is that you are given three cards: an ace, a king and a valet (the order of distribution matters). You stack them on the table in the order you were given them. So you first lay the ace, then the king and finally the valet at the top. Then you are asked to take each card one by one. The first depilated card will be the valet while it was the last stacked. For the ace, it will be the opposite: it will be depilated last while it was stacked first.

The microprocessor stack has exactly the same principle as in this example. The available commands are numerous due to the possibility of indexing with S or U. It is very important to remember the first-last concept that came out.

Disruptions

INTRODUCTION

Interruptions are signals sent by an input-output device of the microprocessor to signal that it needs its services. The microprocessor searches each cycle, i.e. all micro-sedons, a possible interruption, allowing an instant response.

It's a very practical system, because the microprocessor doesn't need to scrutinize the peripherals, it just waits to be warned and continues to run.

CARACTÉRISTIQUES

In response to an interruption, when the processor detects one and it is authorized, it completes the instruction it was performing. It then prohibits other less priority interruptions and stacks PC, CC and possibly other registers. Then plugs into the address of the interruption routine. The interruption being completed, it depilates the stacked records and continues the program that was interrupted.

THE SCREEN SYSTEM

The MOS screen consists of 299 x 32 points, or 64999 points. To avoid devoting one byte to each of these points, they were assembled in packages of eight, then constituting one byte. The screen memory (points) therefore uses 8999 bytes or $1F49 in hexadecimal (not $1FFF as claimed in the MO5 operating instructions). However, this is not enough: indeed, with only 8990 bytes, one can define each point as being lit or turned off but one cannot define its color. That's why 8909 other bytes are allocated to the definition of ink color and background of each byte. So it takes a total of 16999 bytes for the screen. Using addresses from 9 to 16099 would have taken too much space and limited user memory. That's why the manufacturer used a "ruse": the state of the screen points is housed from $009 to $1F49 and the color state from 0999 to $1F49.

How can we accommodate two different things at the same addresses?

This is achieved thanks to the input-output circuit: the bit @ (low weight bit) of the SA7CD address is used to direct the data on the dot status bytes or on the dot color bytes (this allows you to occupy only 1F49 bytes of address on the microprocessor and to have a screen image that corresponds to double the space).

To convince you, type the following: first press the small white button (Initial. prog.), then type POKE 4990.1, so you see a small dot on the screen (the dot is dark blue). Now, type POKE &HA7CD,149: POKE 4900.1: the dot is black on a red dot.

The rule is: if the low weight bit of $A7Cÿ is 1, you act on the screen points. If the same bit is at Q, you act on the color according to the rule:

strong weight quartet for ink, low weight quartet for bottom.

(In our example, 1 is $1, a black ink (9) and a red background (1)).

In fact, the $A70 address is used to define what has just been explained but is also used to define the color around the screen; the organization is as follows:

BACKGROUND AND INK COLORS

As we have just seen, bits 1, 2, 3, 4, of the system variable located in SA7CQ give us the color of the circle of the screen.

To convince you, type POKE &HA7C{Q, 6 and you will see the edge dye in yellow; 6 is written in binary: bits 1, 2, 3, 4 give us 0911 or 3 in decimal which represents the yellow color.

Another address is used to define the color of the ink and background of what is printed on the screen; this is the address $202B (the number of colors being 16, it is enough to code the color of ink and 4 bits to code the color of the background, i.e. 1 byte in total). Quick search: routine address: E899. If the key is pressed C = 1 (carry) otherwise C = 6.

Slow screening: Routine address: E896. The ASCII code of the pressed key is returned to the B accumulator. If no key is pressed, then B = @. A routine of screening can therefore be:

# The optical pencil

Two routines concern this device: one is used to test whether or not the validation contact is open, the other returns the coordinates of the target point.

Microcontact status: Routine address: E81B. If you press the microcontacter, then C = 1 (carry), otherwise C = 6.

Contact details of the target point: routine address: E818. On return: if C = 1, the reading is invalid; ifC = 6, the reading is valid and then we have the abscisse in X (from 9 to 319) and the order in Y (from @ to 199).

= The joystick

Scrutiny address joystick: E827. Input parameter: the joystick number in A (@ or 1). On return: value of handle in B and state of button in C (carry):

C = @ = button dropped, C = 1 +> button pressed.
