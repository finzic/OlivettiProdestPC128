1.1. CARACTÉRISTIQUES

The TO, the latest of THOMSON's microcomputers, includes a central unit, a detachable keyboard, a 3.5-inch (five-inch) disk drive, an optical pencil and several extension connectors. Like all the microcomputers in the THOMSON range, it can be connected to a video monitor or a colour TV by means of the ‘'Peritel' socket.

— The central unit

Battery around the 6809 E microprocessor, to ensure compatibility with TO7 and TO7-70, it has 128 kilobytes of RAM and 136 kilobytes of dead memory.

— Keyboard

Untachable, type AZERTY, it connects to the front of the TO9, next to the RESET button. Unlike its predecessors, it is a real mechanical keyboard, equipped with 81 repeat keys. In addition to the usual character set (alphabetical letters, special characters, etc.), it also includes

1.5. ORGANIZATION OF THE MEMORY

The TO9 has 128 kilobytes of memory. These 128 kilobytes are distributed as follows:

16 kilobytes dedicated to screen memory: they are located in the address field 4000H to S5FFF.

16 kilobytes located in the address field 6000H to 9FFFH.

96 kilobytes divided into 6 memory plans of 16 kilobytes each. Each memory plan occupies the address field AOOOH to DFFFH. These memory plans will be called memory banks.

So we can schematize the memory space of TO9 in the following way.

We called the memory part between 6000H and 9FFH, ‘common user memory' because a program written in machine language will be able to read or write data into any memory bank. On the other hand, a program located in a memory bank will not be able to read or write data in another memory bank.

2.2. The TO9 BASIC commands

AUTO: Control

AUTO n,i n is a line number i is an increment

The AUTO command causes an automatic numbering of the lines of your BASIC program. The first line will have the number n, the second the number n + 1, etc...

4.2. CREATION OF A PROGRAMME
MACHINE LANGUAGE

To create a program in machine language, you must insert into the TO9 memory binary codes understandable by the microprocessor 6 809. Some instructions This particular BASIC will enable you to run this program in machine language. To store a program in machine language you must have a place ‘‘safe'?. Indeed when running a program written in BASIC the variables used in the program are never stored at a fixed address in memory; According to the operations carried out in the programme, these addresses are changed. The variables in the BASIC program could then overwrite the program written in machine language.

We will therefore use CLEAR instruction which will reserve space in memory. This memory area will no longer be used by BASIC.

Use of CLEAR instruction

Recall the operation of the instruction: CLEAR.

CLEAR allows you to reserve space in memory banks or memory space between 6100H and 9FFFH. The maximum address usable by BASIC will be taken in the current bank. So if Bank 5 is the current bank, CLEAR, &HAFFF will reserve the BOOOH addresses to DFFFH in Memory Bank 5 and the whole Bank 6.

CLEAR also allows you to reserve space between 6100H and 9FFH. This should be used when working on multiple memory banks simultaneously.

This memory space will no longer be modified by BASIC even by a NEW instruction.

A programming method may consist of testing whether the asterisk should be displayed between columns 8 and 13 (blue box) or 18 and 23 (red box) and displaying it in blue on a blue background (to make it disappear from the blue box) or in green on a red background (to make it pass in front of the red box) or in green on a black background in other cases. This method would probably work, though somewhat tedious. Fortunately, there is a much simpler method.

In fact, let's draw the blue box, in blue shape color and blue background color, and the red box in red background color and green shape color. For the rest of the screen, we will use a green shape color and a black background color. Then let's freeze the colors on the screen by setting the parameter c of the CONSOLE statement. So when the asterisk will be displayed in the blue box it will take the colors present on the screen, i.e. a blue shape color and a blue background color. It will therefore be invisible giving the viewer the illusion of passing behind the box. Similarly for the red box the asterisk will be displayed in green shape on red background giving the illusion of passing in front of the box.

Thus, it will be sufficient to determine in advance the shape colors

and background of each part of the screen screen to create these relief effects in a program.

5.5. FUNCTION OF SCREEN MEMORY

— 40 column mode

Everything that appears on your TO9 screen is stored in the ‘screen memory'. This screen memory actually consists of two memory planes. A form memory plan (or graphics) and a color memory plan. Its two planes are located at the same physical addresses and it will be selected either by a port. These two memory planes have an identical organization so for one byte of the memory form memorizing a segment of eight consecutive points, corresponds, exactly to the same address, in the color memory, a byte memorizing the background and shape colors of this segment.

Form memory: We saw at the beginning of this chapter that each graphic line breaks down into forty segments of eight points. Thus a graphic line occupies forty bytes in the form memory (one byte per segment of eight points). Each eight-point segment is stored as follows. Each point forming part of the shape of the drawing has the bit associated with it 1. All other bits will be zeroed.

Example: Suppose a segment has the following configuration (black dots are points forming part of the shape of the drawing).

00606600

The byte associated with it in form memory will have the value:

[919111411114] 6] i.e. 2C hexadecimal

or 44 in decimal

How to calculate the address of a segment in the screen memory?

In reality this is very simple. Indeed the first graphic line of the screen occupies the first forty bytes of the screen memory, the second graphic line, the next forty ...

Thus the address in the screen memory of the third segment of the 20th graphic line will be:

This sub-program allows you to assign a shape or background color to a point on the screen. The coordinates of the point are given in the X registers (included between 0 and 319 or 639) and Y (between 0 and 199). The colour is initialized in the FORM variable located at hexadecimal address 6038.

GETPT (E821)
This sub-program returns in the B register the color of a point identified by its X and Y coordinates.

DRAWXY (E80C)

This subprogramme draws a line between the last selected point and the point identified by the coordinates contained in the X and Y registers. The color of the line will be given by the FORME variable (hexadecimal address 6038).
